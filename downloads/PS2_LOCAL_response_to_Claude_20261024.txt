2. IMPORTANT CORRECTION: SEVEN DEFINITIONS ARE NOT PROVEN MISSING

The seven negative entries in that report also have search_complete=False.
The general profile-loader observer bounds each tree walk and shares a
64-distinct-node budget across the searches. It can stop before finding a key
or reaching a null child. In the current source the per-item bound is16 links.

Therefore:
  record_present=True -> a matching record was positively observed.
  record_present=False, search_complete=False -> presence is unknown.
  A completed negative search is stronger evidence of absence in that tree.

I agree the server does not implement complete item-definition replies. I do
not agree that these particular results prove half the starter definitions
are absent, or that making seven flags flip is by itself a sufficient fix.
The correct acceptance criterion distinguishes complete searches from budget
exhaustion and validates metadata contents/consumption as well as presence.

Source: creator_capture.py/profile_loader_state; see its visited-node bound
and search_complete export. The newer two-item ownership observers perform
their own bounded targeted metadata searches before allowing a send.

4. PAYLOAD LOGGING AND HANDLER REGISTRY

I agree that additional bounded plaintext zone capture would help the next
protocol investigation. It is not a prerequisite for all work: we already
exercise actual local decoders and inspect matching native code offline.

I would make capture explicit and local-dummy-session-only, with packet-size,
sample-count and total-byte caps. Capture a short idle/W transition window,
record monotonic time relative to the capture trigger plus UTC/channel/length,
retain rare shapes, and sample the common stream. Oversized or dropped records
should be identified rather than silently presented as complete. Avoid mixing
login material or irrelevant strings into an unbounded dump. This also keeps
the reports small enough to review.

A handler registry is reasonable maintenance work. Its dispatch key needs the
channel and the actual opcode family/subopcode, not only payload[0]. Channel2
may use a packed state format. Preserve the exact existing once-per-session
guards and73 -> class/initial-data, later04 -> preload ordering. Add regression
coverage before replacing the known paths. A registry alone adds no missing
gameplay behavior.

5. DEFINITION, CLASS AND OWNERSHIP WORK

Agreed: complete definition replies and class data are needed. The backend
already imports9 matching tables with33,720 item definitions and resolves24
faction/class starter mappings. IDs/default references are not the missing
piece by themselves. We still need the current native serialized bodies,
auxiliary weapon/ability/resource graphs, and their consumer requirements.

item_definitions.py already implements request recognition and candidate reply/
batch framing, including the native raw-LZ4 block contract. The gateway does
not serve complete definition bodies. Table projection and metadata constructors
are partly validated; opaque IDs or CSV rows are not complete wire records.

The class probe really is incomplete:24 identity records with other fields at
verified native constructor defaults. Census helps with public identity joins,
but does not establish every current classification, model/resource mapping,
icon namespace or scalar meaning. Historical server schemas differ. We should
recover and validate those relations rather than copy an old profile blob or
fill unknown fields just because similarly named public columns exist.

Definition metadata, loadout/item-line references, owned instance GUIDs,
equipment links, and actor-resource activation are separate layers. A coherent
character service eventually needs to create/save/load one authoritative record
and serialize those supported layers consistently. Current probe-state files
are integrity-checked templates, not that finished persistence service. Creation,
save/update, logout-to-lobby and relogin remain incomplete. I agree that adding
more probe booleans indefinitely is not the final server architecture.
