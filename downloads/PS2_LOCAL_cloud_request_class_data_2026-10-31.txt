WHAT WE SEND TODAY (and what is empty)
1. ReferenceData "ProfileDefinitions" (our build's equivalent of your old
   ClientProfileData, 1703): 24 class records, each 90 bytes. We fill only
   the profile id, the name id (e.g. 114 for VS Light Assault) and a type id.
   Everything else is zero. Our reader layout: 7 leading u32 words, nested
   maps of (key, two values) entries, then a two-float tail. Codex compared
   it with the old record: old had 9 leading words, pair-map entries and a
   four-float tail. Profile 19's old record names id 114 and models 165/166.
2. SendSelfToClient "profiles" list: ONE entry (profile 19, 102 bytes) with
   only the profile id set, and currentProfile 19. Our client reads an entry as:
   7 u32, a nested collection, 2 u32, u8, 14 u32, u8.
The real capture had 25 profiles in SendSelf.
